* `gg_varpro()` now scores the boxes, z and the new `coverage` column from one set of release rules, the way `varPro::importance()` does, so they always describe the same trees. Before, z followed `max.tree` passed through `...` while the boxes stayed on the fit-time trees, and a variable with rules only outside those trees was dropped without a warning (#340)
* `gg_varpro(local.std = )` now reaches varPro. It was always sent as `FALSE`, so the default z was the winsorised mean over the winsorised SD rather than `importance()`'s default. **The default z, and so the set of variables above `cutoff = 0.79`, changes**, and with `local.std = TRUE` it depends on the random number stream, as in varPro: call `set.seed()` first. The boxes are no longer divided by a plain `sd()`; with `local.std = TRUE` the per-tree values are already on z's scale. The class-conditional z follows the same setting (#340)
* `gg_varpro()` reports an undefined z (a variable tested in under `trim` of the trees, with `local.std = FALSE`) as `NA` instead of 0, and adds `coverage` and `tested` to `$imp` and `$stats`. `plot.gg_varpro()` draws untested variables as open boxes with a caption, so a barely-tested variable no longer reads as "no importance". `trim`, `max.tree` and `max.rules.tree` are now arguments; any other argument in `...`, which used to go to `importance()`, is an error (#340)
